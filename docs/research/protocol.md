# Research Protocol

## 1. Research Objective

This coursework studies what different forms of explanation and intervention can establish about a **fixed local behavior of a generative language model**.

The primary conceptual reference is Schneider (2024), *Explainable Generative AI (GenXAI): A Survey, Conceptualization, and Research Agenda*.
The project follows the paper's emphasis on explanation desiderata, scope, foundational sources, required model access, self-explanation, and mechanistic interpretability rather than treating GenXAI as a catalogue of unrelated techniques.

The core research question is:

> **For a fixed local generative behavior, what complementary evidence about its explanation is provided by model self-explanation, input attribution, controlled input perturbation, and internal activation intervention, and where do these forms of evidence agree or disagree?**

The project does **not** attempt to rank XAI methods, assign a ground-truth faithfulness score, explain an entire language model, or demonstrate as many techniques as possible.

The study uses one coherent experiment:

```text
controlled input contrast
        ↓
fixed model behavior and target score F
        ├── self-explanation
        ├── input attribution
        ├── controlled input intervention
        └── internal activation intervention
        ↓
compare what each form of evidence supports
```

The experimental effort should remain small.
The main effort is expected to be understanding the mathematical assumptions, evidential meaning, and limitations of the methods.

## 2. Connection to Schneider's GenXAI Framework

Schneider distinguishes explanation properties from the properties and requirements of the mechanism used to produce them.
Relevant dimensions for this project include:

- **output scope**: focused rather than holistic;
- **interaction scope**: a single input-output relation rather than an entire dialogue;
- **foundational source**: primarily the model and prompt;
- **required model access**: black-box-compatible for self-explanation and behavioral perturbation, white-box for gradients and activations;
- **model self-explainers**: explanation generated by the model itself versus explanation produced by another algorithm;
- **sample difficulty**: simple calibration cases can differ from harder research cases;
- **desiderata**: especially faithfulness, plausibility, completeness/minimality, sensitivity, and robustness.

The project deliberately studies a **focused output property** because generative outputs contain many possible attributes and decisions.
Explaining one precisely defined behavior is methodologically clearer than claiming to explain an entire generated response.

The project also preserves an important distinction from Schneider's discussion: established categories such as **feature attribution** and **mechanistic interpretability** are useful labels but are not fully orthogonal dimensions.
Feature attribution primarily characterizes the form of an explanation, while mechanistic interpretability characterizes what internal computation is investigated and how it is reverse-engineered.
They are therefore not treated as competing methods in a benchmark.

The relationship between the experiment components and the paper is:

| Component | Schneider-oriented interpretation | Access in principle | Evidence produced |
| --- | --- | --- | --- |
| Self-explanation | Self-explainer; prompt/model as sources; dynamic textual explanation | Black-box compatible | What the model states mattered |
| Integrated Gradients | Model-based feature attribution; focused local explanation | White-box | Local input sensitivity along a defined path |
| Controlled input perturbation | Prompt/input intervention with observed model behavior | Black/grey-box depending available scores | Behavioral effect of a predefined input change |
| Activation patching | Model-based mechanistic interpretability / causal tracing | White-box | Effect of a specified internal intervention |

Self-explanations are **not assumed to be faithful** merely because they are plausible or understandable.
Attribution values are **not assumed to identify a causal mechanism**.
Activation patching provides causal evidence about the specified intervention and input contrast, not a complete description of the model's reasoning.

## 3. Experimental Behavior and Target Score

### 3.1 Model behavior

Use a small open-weight autoregressive language model that:

- exposes logits, gradients, and intermediate activations;
- can run the complete experiment on available coursework hardware;
- is supported by maintained libraries;
- requires no training or fine-tuning for the core study.

The exact model, checkpoint revision, tokenizer revision, numerical dtype, and software versions must be frozen before final runs and recorded in the experiment configuration.

### 3.2 Controlled input contrast

Each analyzed case consists of a pair:

\[
x^{\mathrm{clean}},\; x^{\mathrm{contrast}}
\]

that differs in a small, semantically controlled factor chosen **before** inspecting explanation outputs.

`clean` and `contrast` are operational names only.
The pair should be designed so that the changed factor is clear enough to support interpretation without requiring a large benchmark.

The preferred design keeps the task and wording as similar as possible while changing one factor relevant to the selected behavior.

Use:

1. **calibration cases**, where the intended contrast and model behavior are easy to inspect;
2. **research cases**, where the same protocol is applied to a more interesting controlled factor.

Calibration and research cases use the same scoring and explanation procedures.
Calibration cases are not reported as evidence of broad generalization.

### 3.3 Focused target score

The experiment uses one scalar target score \(F\) consistently across attribution, input intervention, and activation intervention.

For a next-token contrast between target token \(y^+\) and alternative token \(y^-\), the preferred score is the logit difference

\[
F(x) = z_{y^+}(x) - z_{y^-}(x),
\]

where \(z_y(x)\) is the pre-softmax logit for token \(y\) at the fixed generation position.

A logit difference is preferred because it is continuous and directly tied to the contrasted model behavior without introducing probability saturation.

Whenever possible, select cases whose contrasted outputs are represented by single tokens under the frozen tokenizer.
If a research case requires a short multi-token target, its sequence-level score must be defined and frozen before final runs; it must not be changed per example.

The same \(F\) must be used for:

\[
\text{attribution},
\qquad
\Delta F_{\mathrm{input}},
\qquad
\Delta F_{\mathrm{patch}}.
\]

This common mathematical object is the main link between the methods.

### 4. Explanation and Intervention Methods

#### 4.1 Model self-explanation

After the model behavior has been obtained under the fixed task prompt, elicit a concise natural-language explanation of that behavior.

The explanation prompt must not define or alter the primary behavior being measured.
The target decision/output is fixed first; self-explanation is collected separately.

The self-explanation is treated as:

\[
E_{\mathrm{self}}(x, y),
\]

a model-generated statement about the behavior.

The analysis asks whether the explanation mentions the controlled factor or makes other testable claims.
It does **not** use an LLM judge, embedding similarity, or an automatically constructed "faithfulness score".

A fluent or plausible self-explanation is not treated as evidence that it reflects the model's internal computation.

#### 4.2 Integrated Gradients

For input embedding representation \(e\), baseline \(e'\), and target score \(F\), Integrated Gradients for dimension \(i\) is

\[
IG_i(e) = (e_i-e'_i)
\int_0^1
\frac{\partial F(e' + \alpha(e-e'))}
{\partial e_i}
\,d\alpha .
\]

The integral is approximated numerically using a fixed integration procedure.

Embedding-dimension attributions are aggregated into token-level values using one frozen aggregation rule.
If \(R\) is the predefined token region corresponding to the controlled factor, a descriptive regional attribution can be reported as

\[
A_R = \sum_{i \in R} A_i.
\]

The project uses Integrated Gradients because it has a clear axiomatic motivation and exposes the relation between gradients, path integration, and local sensitivity.

The numerical implementation should verify the Integrated Gradients completeness relation to the extent expected from numerical approximation:

\[
\sum_i IG_i
\approx
F(e)-F(e').
\]

This is a **sanity check on the attribution computation**, not a measure that proves explanation faithfulness.

### Baseline and path

The baseline is a methodological choice and must be justified and frozen before final experiments.

For decoder-only language models, do not invent a trained mask token if the model has none.
Do not switch baselines or path methods on individual examples to obtain more desirable explanations.

Vanilla Integrated Gradients uses a straight path in embedding space; intermediate points need not correspond to natural text.
This limitation must be reported.
Sequential Integrated Gradients may replace vanilla IG only through an explicit protocol revision motivated by the feasibility study, not as a per-example fallback.

#### 4.3 Controlled input intervention

The primary behavioral intervention uses the predefined input contrast rather than deleting whichever token receives the highest attribution.

Define

\[
\Delta F_{\mathrm{input}} = F(x^{\mathrm{contrast}}) - F(x^{\mathrm{clean}}).
\]

This measures the behavioral effect of the controlled input change.

Because the contrast is designed before attribution is inspected, the intervention is not selected post hoc to validate the attribution map.

The result is interpreted as evidence about this specific input manipulation.
It does not imply that all semantic equivalents or nearby prompts would behave the same way.

#### 4.4 Activation patching

Activation patching is used as a small mechanistic intervention, not as an exhaustive circuit-discovery project.

For the core experiment:

1. run \(x^{\mathrm{clean}}\) and cache the selected internal activation;
2. run \(x^{\mathrm{contrast}}\);
3. replace the corresponding activation in the contrast run with the cached clean activation;
4. recompute the same target score \(F\).

For an activation \(h_{\ell,k}\) at layer \(\ell\) and location \(k\),

\[
\Delta F^{\mathrm{patch}}_{\ell,k} = F\!\left( x^{\mathrm{contrast}}; do(h_{\ell,k}=h_{\ell,k}^{\mathrm{clean}}) \right) - F(x^{\mathrm{contrast}}).
\]

The core study uses **denoising patching** from clean to contrast.

To keep the experiment minimal, the default scope is:

- one pre-specified token position or controlled-factor region;
- residual-stream activations;
- a sweep across layers.

The project does not perform head-by-head circuit discovery, path patching, sparse-feature discovery, or exhaustive neuron analysis unless the research protocol is explicitly revised.

A positive denoising patching effect is interpreted as evidence that restoring the selected clean activation is sufficient to restore some of the target behavior under the chosen contrast.
It does not establish a complete mechanism, necessity, or a human-readable reasoning algorithm.

### 5. Experimental Procedure

#### 5.1 Feasibility study

Before final experiments:

1. select a candidate open-weight model and confirm that logits, gradients, and activations are accessible;
2. verify that the chosen target outputs have stable tokenizer representations;
3. verify that the controlled input contrast produces a measurable change in \(F\);
4. verify the Integrated Gradients implementation and baseline behavior;
5. verify that residual-stream activation patching can be performed cleanly;
6. use these results only to finalize the protocol and implementation choices, not as reported experimental results unless explicitly retained.

The feasibility study may change implementation choices such as model checkpoint, baseline, or exact controlled cases.
Any change that affects the scientific method must be reflected in this protocol before the final experiment is frozen.

#### 5.2 Freeze before final runs

The frozen model and tokenizer are `Qwen/Qwen3-0.6B` at revision
`c1899de289a04d12100db370d81485cdf75e47ca`.
Use float32 weights and input embeddings, eager attention, evaluation mode,
and no TF32 matrix multiplication.
The repository lockfile records the selected software versions.

Each case has one fixed question with options A and B. Its clean input uses
`Cue: {correct label}` and its contrast uses `Cue: {alternative label}`;
the question, options, and all other prompt text are identical.
The frozen cases are below; `\n` denotes a newline within a question:

| Role | Question and options | Correct \(y^+\) | Alternative \(y^-\) |
| --- | --- | --- | --- |
| Calibration | `What is the capital of France?\nA) Paris\nB) Berlin` | A | B |
| Research: arithmetic | `What is 7 + 5?\nA) 13\nB) 12` | B | A |
| Research: logic | `All cats are mammals. Mira is a cat. Is Mira a mammal?\nA) Yes\nB) No` | A | B |

Append `\nCue: {cue label}\nAnswer with only A or B.` to the question and
options. Render this as one user message with Qwen3's chat template,
`add_generation_prompt=True`, and `enable_thinking=False`. Read the A/B
logits at the first answer-content position after the complete rendered
prefix; do not generate reasoning tokens before scoring. Confirm that both
labels are single tokens under the frozen tokenizer. For each case,
\(F=z_{y^+}-z_{y^-}\), so a larger score always favors the correct label.
The clean and contrast inputs must have equal token length and differ at only
one tokenizer-aligned cue token. The controlled-factor region is that token.
\(\Delta F_{\mathrm{input}}\) retains the definition in §4.3.

After scoring the primary input, choose the higher-logit label from A and B
and elicit self-explanation with a separate non-thinking user message:

```text
{question and options}
Cue: {correct label}
The selected answer label was {selected label}. In one sentence, explain why that label was selected.
```

Generate greedily with `do_sample=False`, `max_new_tokens=64`, and the
tokenizer's EOS token as the padding token. This statement is prompted with
the already fixed decision and is not independent evidence of the decision's
cause.

For IG, hold the chat-template structural token embeddings fixed. At every
user-content position, use the embedding of the tokenizer's ordinary space
token as the artificial space-token embedding baseline; retain the same
length, attention mask, and positions. This is an artificial embedding
reference, not a natural-language empty prompt. Attribution is relative to
the straight embedding path from this reference to the clean input. Use
Captum's `riemann_middle` rule and 1024 steps, as supported by the calibration
convergence study. Sum embedding dimensions with their signs to obtain each
token attribution. Always record the completeness delta as a numerical
diagnostic. Fail on non-finite values or computation errors; do not apply a
fixed pass/fail threshold to a finite residual. If a finite residual is large enough that the attribution sum does not reasonably approximate \(F(e)-F(e')\), report the attribution as numerically unreliable and do not interpret it as normal IG evidence.

For activation patching, at each decoder layer,
replace only the full residual-stream output vector at the aligned cue token
in the contrast run with its clean-run value, then recompute \(F\). The
calibration smoke test checks layer 0; the final experiment sweeps all layers.
A weak effect at a late layer does not imply that the cue is irrelevant:
information may have propagated to other positions. This sweep does not
identify a complete circuit or information flow.

The case list above is the final experiment manifest. Record exact installed
software versions, commands, hardware, prompts, token IDs, and numerical
outputs with reported results; do not treat the feasibility case as a final
scientific result.

#### 5.3 Final run sequence

For each frozen case:

1. compute the model behavior and target score for clean and contrast inputs;
2. record the model output;
3. collect the self-explanation;
4. compute Integrated Gradients for the clean behavior;
5. record token-level attribution and the predefined controlled-factor region;
6. compute \(\Delta F_{\mathrm{input}}\);
7. perform the frozen activation-patching sweep;
8. save the small numerical outputs required to reproduce figures and tables.

Do not edit individual prompts, target definitions, or method settings after seeing the result merely to obtain a clearer or more desirable explanation.

Negative, weak, ambiguous, and inconsistent cases remain part of the experimental record.

### 6. Analysis and Interpretation

The experiment uses **triangulation**, not a method leaderboard.

For each case, compare:

- what the self-explanation claims mattered;
- where Integrated Gradients assigns relevance;
- the observed effect of the predefined input intervention;
- the layer-wise effect of the internal activation intervention.

The primary outputs are descriptive and case-level:

- \(F(x^{\mathrm{clean}})\);
- \(F(x^{\mathrm{contrast}})\);
- \(\Delta F_{\mathrm{input}}\);
- token-level IG values;
- optional \(A_R\) for the pre-specified controlled-factor region;
- \(\Delta F^{\mathrm{patch}}_{\ell,k}\) across layers;
- the original self-explanation text.

The study does **not** define an arbitrary threshold such as "faithful if correlation \(> c\)" and does not combine the methods into a weighted overall score.

Small aggregate summaries may be reported when they directly summarize the frozen cases, but they must be descriptive rather than presented as population-level inference.

#### 6.1 What agreement means

Agreement between explanation forms can provide converging evidence about the selected local behavior.

For example, a case may show that:

- the model names the controlled factor in its self-explanation;
- the factor receives substantial attribution under the chosen IG path;
- changing the factor changes \(F\);
- restoring its internal representation at selected layers changes \(F\) toward the clean behavior.

Such agreement is evidence about the analyzed behavior under the frozen experimental design.
It is **not proof** that the natural-language explanation exactly reproduces the model's reasoning process.

#### 6.2 What disagreement means

Disagreement is a valid result.

Examples include:

- the model names a factor that has little observed effect under the controlled intervention;
- IG emphasizes tokens outside the manipulated factor;
- an input change strongly affects behavior while the self-explanation does not mention it;
- activation patching shows weak or distributed effects rather than a localized layer.

Disagreement should be analyzed in terms of method assumptions and scope rather than "fixed" by changing the example.

#### 6.3 Claim boundaries

The following distinctions must be preserved in the report and presentation:

\[
\text{plausibility} \neq \text{faithfulness},
\]

\[
\text{attribution} \neq \text{causal mechanism},
\]

\[
\text{local gradient sensitivity} \neq \text{finite intervention effect},
\]

\[
\text{positive patching effect} \neq \text{complete mechanistic explanation},
\]

\[
\text{agreement} \neq \text{proof},
\]

\[
\text{disagreement} \neq \text{automatic method failure}.
\]

The project therefore studies **evidence relevant to explanation faithfulness** rather than claiming to directly measure a ground-truth faithfulness quantity.

### 7. Reproducibility and Scope

#### 7.1 Reproducibility record

Record enough information to rerun every reported result:

- model identifier and exact checkpoint revision;
- tokenizer identifier and revision;
- Python and library versions;
- relevant library configuration;
- hardware device and numerical dtype where relevant;
- prompts and controlled prompt pairs;
- tokenizer representation of target outputs;
- target-score definition;
- generation settings;
- random seeds where stochasticity is used;
- self-explanation prompt;
- IG baseline, path method, integration steps, and aggregation rule;
- input-intervention definition;
- activation location and patch direction;
- commands used for final runs;
- small numerical outputs used to produce reported figures and tables.

The code should obtain external models through documented instructions.
Do not commit model weights, caches, large datasets, or generated artifacts that are not needed for reproduction.

#### 7.2 Core scope

The core experiment contains:

- one small open-weight language model;
- one fixed target-score definition;
- one controlled-contrast design;
- self-explanation;
- one gradient-based attribution method;
- one controlled input intervention;
- one focused activation-patching intervention.

#### 7.3 Explicit non-scope

The core experiment does not include:

- model training or fine-tuning;
- large-scale benchmarking;
- production inference infrastructure;
- agent frameworks;
- RAG pipelines;
- attention-as-explanation demos;
- SHAP/LIME method comparisons;
- probing classifiers;
- sparse autoencoders;
- full circuit discovery;
- human-subject evaluation;
- automatic LLM judging of explanations;
- a composite "XAI score".

RAG remains relevant to Schneider's discussion of verifiability and lineage, and sparse autoencoders remain relevant to later mechanistic-interpretability research, but both introduce separate research questions and are outside the minimal core experiment.

#### 7.4 Expected coursework artifacts

Reported figures should be generated from frozen experimental outputs and may include:

1. one token-attribution visualization;
2. one compact table or plot showing the controlled input effect;
3. one layer-wise activation-patching plot;
4. representative self-explanations shown alongside the corresponding numerical evidence.

The report and presentation must distinguish:

- claims taken from Schneider (2024);
- claims from later methodological literature;
- observations produced by this repository.
